Doppler: draft paper vs. codebase

This page compares the Doppler defense as described in the draft paper with what the codebase implements. Every claim cites the paper section or equation and the source file and line, so each one can be checked independently.

Paper: Doppler-security-26 (draft, Aug 2026) Code: main @ aed64a1 Audited: 27 Oct 2026 Paths are relative to the repository root
Bottom line

What the code calls “Doppler” is a traffic-driven MILP that changes the topology as little as possible while keeping link utilization under a cap. None of the paper’s security machinery is implemented: there is no attack-plan transferability τ, no history of past states, no reconnaissance-to-plan pipeline, and no random choice among safe topologies. The objective also runs opposite to both the paper’s security objective and the older Gurobi implementation.

How the code implements Doppler

The active path, in call order, for one traffic-matrix step.

  1. Dispatch. exp-v2.py builds a Simulation with tp="Doppler". The name is matched case-insensitively to the doppler registry entry and run by _run_milp_method.scripts/Doppler/exp-v2.py · src/onset/method_registry.py:73-82 · src/onset/handlers.py:21-61
  2. Inputs. The current traffic-matrix row, the fiber graph, the current logical graph and per-node transponder counts go to build_optimization_problem.src/onset/simulator.py:356-368, 617-631 · src/onset/preprocessing.py:632
  3. Candidate links come from graph structure only. max is every node pair exactly two hops apart. conservative closes triangles around the top 10% of links by betweenness.src/onset/preprocessing.py:168-248
  4. Tunnels. Each demand may only use edges on short precomputed paths over the fiber graph plus candidates.src/onset/preprocessing.py:283-418
  5. MILP. Binary x_e per link, a transponder degree limit, flow conservation, f ≤ x activation, per-edge load ≤ MLU ≤ min(1, threshold) and root-flow connectivity. The objective is minimize 2·(links added + dropped) + MLU.src/onset/open_doppler.py:43-302 (objective 231-245)
  6. Enumeration. Repeated solves, each adding a no-good cut that forbids the previous answer, until top_k, infeasibility or the time budget.src/onset/open_doppler.py:616-874
  7. Choice and evaluation. The lowest-MLU solution (then fewest changes) is applied by dropping, then adding, circuits. Traffic is then routed with ECMP, MCF or SMORE.src/onset/base_types.py:366-377 · src/onset/simulator.py:569-578

A. The core security objective

1
The objective is invertedCore
Paper

Minimize T(G′), the worst-case transferability of recent attack plans. Even the “original motivation” maximizes structural difference, min |Eₜ ∩ E′|.

§4.8 Eq. 18, 21–22 · §4.11 Eq. 25
Code

Minimizes changes. Each change costs 2 and MLU is capped at 1, so “change nothing” wins whenever it is feasible.

Bugs that affect any results

Independent of the paper, these change what the current code produces.

Demands are silently dropped depending on direction Core

Tunnels are keyed by string-sorted node pairs, but demands cover every ordered pair. Any demand (s,t) with s > t gets no flow variables and disappears from the MILP. On ANS with ANS_coremelt_links-2_volume-2.00e+11.txt, on the row the simulator reads first (the last row), 15 of 24 nonzero demands are dropped, about 70% of volume.

src/onset/preprocessing.py:145-152, 567 · src/onset/open_doppler.py:74, 96, 131
The tunnel cache ignores the candidate set Major

The cache key is only the network name and caching is always on. A conservative run poisons a later max run, so results in a mixed grid depend on run order.

src/onset/preprocessing.py:421-442 · src/onset/simulator.py:628
The latest driver cannot run an experiment as written Major

main() always prints commands and calls exit(). Each printed command has 10 fields, but the unpack expects 9. Gigapop and CEN are not in data/, and the hosts dict has the key "Gigalpop".

scripts/Doppler/exp-v2.py:211-216 · scripts/Doppler/experiment_params.py:68
No-good cuts pile up Minor

Every earlier cut is re-added on every loop pass, so the model grows quadratically with the number of solutions.

src/onset/open_doppler.py:666-678
max returns each candidate twice Minor

On ANS that is 78 entries for 39 unique links, because pairs come from permutations. The MILP de-duplicates them later, so this is harmless.

src/onset/preprocessing.py:195, 216

How to verify

Two checks reproduce the most consequential findings.

The objective change

Compare the legacy and current objectives, then read the commit that introduced the current one.

sed -n 955,970p src/onset/gurobi_optimization.py; sed -n 1087p src/onset/gurobi_optimization.py

Dropped demands

Run from the repository root. It builds the tunnels without touching the on-disk cache and counts demands with no tunnel.

import sys, tempfile; sys.path.insert(0, "src")
from itertools import permutations
import networkx as nx
from onset.preprocessing import (compute_candidate_links, build_super_graph,
    find_original_tunnels, compute_tunnels, load_demand_from_file)

G = nx.relabel_nodes(nx.Graph(nx.read_gml("data/graphs/gml/ANS.gml", label="id")), str)
pairs = {tuple(sorted(p)) for p in permutations(G.nodes, 2)}
ol, od = find_original_tunnels(G, pairs)
S = build_super_graph(G, compute_candidate_links(G, "conservative"))
_, _, tunnels = compute_tunnels(S, pairs, ol, od, parallel=False, use_cache=False)

rows = open("data/traffic/ANS_coremelt_links-2_volume-2.00e+11.txt").read().split("\n")
with tempfile.NamedTemporaryFile("w", suffix=".txt", delete=False) as f:
    f.write([r for r in rows if r.strip()][-1])
dem = {k: v for k, v in load_demand_from_file(f.name, nodes=tuple(G.nodes)).items() if v > 0}
missing = {k: v for k, v in dem.items() if k not in tunnels}
print(len(missing), "of", len(dem), "demands dropped,",
      round(sum(missing.values()) / sum(dem.values()), 3), "of volume")
